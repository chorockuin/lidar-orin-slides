# PointPillars (LiDAR 3D 객체 검출) 구조·원리 설명 웹 슬라이드 — 요구사항 정의서

> 상태: **확정 v1** · 작성일: 2026-09-25
> CenterPoint 요구사항 정의서(`../centerpoint/requirements.md`)와 같은 틀·원칙을 따름. 사용자 답변(8장)은 CenterPoint 때의 답을 그대로 준용했고, PointPillars에서 새로 정해야 했던 저장소 방식(Q7)은 확정됨.

---

## 1. 목적

NVIDIA Jetson **AGX Orin**에서 동작하는 **PointPillars LiDAR 공식 모델**의 구조와 동작 원리를,
**입력(포인트 클라우드) → 출력(3D 바운딩 박스)** 까지 하나의 흐름으로 이해할 수 있는 **HTML 웹 슬라이드**로 만든다.
학습 원리와 Orin 배포(TensorRT) 실무까지 포함한다.

## 2. 대상 독자 · 용도

- **용도: 자습 후 발표.** 슬라이드 자체만 읽어도 이해되는 자습 자료이면서, 그대로 발표에 쓸 수 있어야 한다.
  - 화면(발표용)에는 그림·핵심 문장만, 상세 설명은 펼쳐보기/노트 패널(자습용)로 분리한다.
- 딥러닝/LiDAR 인식 **초보자**가 끝까지 따라올 수 있어야 한다.
- 동시에 실제 구현을 다루는 엔지니어가 봐도 **텐서 shape·연산 수준까지 정확**해야 한다.
- → "직관(왜?) 먼저, 수식·shape(어떻게?)는 그다음" 순서로 층을 나눠 설명한다.
- CenterPoint 슬라이드를 이미 본 독자도 있으므로, 두 모델이 **갈라지는 지점**(pillar vs sparse 3D conv, anchor vs center)을 명시적으로 비교한다.

## 3. 대상 모델 (확정)

- **NVIDIA 공식 `NVIDIA-AI-IOT / CUDA-PointPillars`** (`Lidar_AI_Solution`의 submodule, TensorRT 기반, AGX Orin 대상 배포 예제)
- 데이터셋: **KITTI** (3클래스: Car, Pedestrian, Cyclist) — 공식 모델이 KITTI로만 제공됨
- 원 모델: PointPillars (Lang et al., CVPR 2019), OpenPCDet `pointpillar.yaml` 설정으로 학습한 체크포인트 `pointpillar_7728.pth`

아래 수치는 공식 저장소 소스·설정·ONNX 그래프로 검증함 (2026-09-25, main `ce7e2bd` 기준).

| 단계 | 구성 | 검증된 사양 |
|---|---|---|
| 입력 | KITTI Velodyne HDL-64E, 단일 sweep, 카메라 시야(FOV) 안의 점만 사용 | fp32 `[N, 4]` = x, y, z, intensity (최대 300,000점, 넘으면 잘라냄) |

| Neck (업샘플·결합) | ConvTranspose 3개 | 블록1: 1×1 s1 64→128 / 블록2: 2×2 s2 128→128 / 블록3: 4×4 s4 256→128, 모두 `[128,248,216]` → concat `[1,384,248,216]` |

| Anchor | 클래스별 1종 크기 × 2방향 | Car 3.9×1.6×1.56 (바닥 −1.78 m), Pedestrian 0.8×0.6×1.73 (−0.6), Cyclist 1.76×0.6×1.73 (−0.6). 크기 순서 = (dx 길이, dy 폭, dz 높이). anchor 중심 `x_a = 0 + col·69.12/215`, `y_a = −39.68 + row·79.36/247` (align_center=False → 간격 ≈0.3215 m), `z_a = 바닥 + h_a/2` |
| 후처리 | CUDA decode + thrust 정렬 + CUDA rotated NMS(마스크) + 호스트 마스크 순회 | anchor별 sigmoid 최대 클래스 score ≥ 0.1 → 디코드: `x = x_a + Δx·d_a`(d_a = √(dx_a²+dy_a²)), `z = z_a + Δz·dz_a`, `dx = exp(Δdx)·dx_a`, `θ = θ_a + Δθ` → 방향 보정 `yaw = limitπ(θ − 0.78539) + 0.78539 + π·dir_label` → score 내림차순 정렬 → **클래스 무관** BEV rotated NMS IoU **0.01** (사전/사후 개수 제한 없음) |
| 출력 | 박스 목록 | 9 값: x, y, z, dx, dy, dz, yaw, class id, score (구조체 필드명은 w, l, h이지만 실제 값 순서는 dx, dy, dz) |
| 학습 | OpenPCDet `pointpillar.yaml` | anchor 할당: BEV IoU 매칭(Car 양성 ≥0.6 / 음성 <0.45, Ped·Cyc 0.5 / 0.35, 사이는 무시). 손실: Sigmoid Focal(α=0.25, γ=2) ×1.0 + Weighted Smooth L1(β=1/9, 각도는 sin 차이) ×2.0 + 방향 분류 CE ×0.2. 증강: GT 샘플링(클래스당 15개), x축 뒤집기, 회전 ±45°, 크기 0.95~1.05. | 배포 | Orin, CUDA 11.4 · cuDNN 8.9.0 · **TensorRT 8.6.11**, FP16 | ONNX를 graphsurgeon으로 수정(전처리·후처리 제거, scatter를 플러그인으로 교체) → `trtexec --fp16 --plugins=libpointpillar_core.so`. Orin 지연(FP16, KITTI train 7,481장 평균): 복셀화 0.18 / 백본+Head 4.87 / 디코드+NMS 1.79 ms, 합계 **6.84 ms (≈146 FPS)**. 정확도(KITTI val 3,769장, 3D moderate AP@R11): Car 77.00 / Ped 52.50 / Cyc 62.26 (OpenPCDet 77.28 / 52.29 / 62.68) |

## 4. 콘텐츠 요구사항

### 4.0 설명 원칙 — **개념이 먼저, 구현은 그다음** (최우선)
- 이 슬라이드의 주인공은 **PointPillars라는 모델의 원리와 발상**이다. "Orin에서 어떻게 구현했나"는 그 원리를 실제로 돌리는 방법으로서 뒤따르는 부차적인 층이다.
- 각 슬라이드는 다음 순서를 지킨다.
  1. **핵심 질문** — 이 단계가 풀려는 문제를 한 문장 질문으로 던진다. (예: "3D 합성곱은 느린데, 점 구름을 그냥 2D 이미지처럼 다룰 수는 없을까?")
  2. **직관·비유** — 수식 없이 그림과 일상적인 비유로 답의 방향을 보여준다.
  3. **원리** — 왜 그 방법이 문제를 푸는지, 다른 방법(대안)은 왜 덜 좋은지.
  4. **수식·shape** — 원리를 행렬 연산과 텐서 모양으로 정확히 확인한다.
  5. **구현 메모 (Orin)** — 같은 개념이 CUDA-PointPillars에서 어떤 모듈로 돌아가는지. 작게, 또는 노트 패널로.
- 구현 세부(atomic 연산, 플러그인 등록, 호스트 마스크 순회 등)는 개념 이해에 필요한 만큼만 화면에 두고 나머지는 노트 패널로 보낸다.
- "왜?"에 답하지 못하는 설명은 넣지 않는다. 숫자 하나도 "이 값이 왜 이 크기인지"를 함께 말한다. (예: 69.12 = 432×0.16, 432와 496은 백본 stride 8로 나누어떨어짐)

### 4.1 전체 흐름 (필수)
- 초반에 **전체 파이프라인 지도**를 보여주고, 이후 모든 슬라이드 상단에 "현재 위치"를 표시한다.
- 각 단계마다 반드시:
  1. **무엇을 하는가** (동작)
  2. **무엇을 의미하는가** (입력 shape → 출력 shape)
  3. **왜 그렇게 설계했는가** (대안과 비교)

### 4.3 수학·shape 설명 (필수)
- 모든 주요 텐서의 **shape 표기** (예: `[N_points, 4]`, `[P, 32, 10]`, `[1, 64, 496, 432]`, `[1, 384, 248, 216]`).
- 핵심 연산은 **행렬 연산 형태로 풀어서** 보여주고, 작은 숫자 예시(toy example)에 실제 값을 대입해 한 번 더 보여준다.
  - 좌표 → pillar 인덱스, 10채널 특징 증강, PFN 행렬곱 + max, scatter, anchor 좌표, 박스 인코딩/디코딩, 방향 보정, IoU 매칭, focal loss.

## 5. 시각·인터랙션 요구사항

- **형식**: 단일 HTML 파일(브라우저에서 바로 열림, 설치 불필요).
- **단계별 진행**: 클릭 / →, Space 키마다 **한 단계씩** 요소 등장·애니메이션 진행. ← 키로 되돌아가기.
- **동적 시각화**
  - 포인트가 위에서 떨어져 기둥(pillar)으로 묶이는 애니메이션
  - 한 기둥의 점들이 10채널로 불어나고, 선형층 → max로 64차원 벡터 하나가 되는 과정
  - 기둥 벡터가 격자에 꽂혀 가짜 이미지가 되는 scatter 애니메이션
  - 텐서 블록(직육면체)이 단계마다 크기·채널이 변하는 모습
  - 한 칸 위에 anchor 6개가 겹쳐 놓이고, 회귀값에 따라 이동·변형되는 모습
  - score가 높은 박스가 남고 겹친 박스가 지워지는 NMS 애니메이션
  - 행렬 곱 셀 단위 하이라이트
- 진행 표시(현재 슬라이드/단계), 목차 바로가기, 자습용 상세 설명 패널(펼쳐보기).
- 다크/라이트 모드 가독성, 16:9 발표 화면 기준.
- CenterPoint 슬라이드와 **같은 디자인·조작 방식**을 쓴다 (두 자료를 이어서 볼 수 있도록).

## 6. 품질 요구사항

- 수치는 **공식 저장소 설정값 기준**. 불확실한 값은 "예시값"으로 명시.
- 원 논문과 공식 구현이 다른 곳은 둘 다 적고 차이를 밝힌다. (예: 원 논문은 9채널 특징, OpenPCDet 구현은 z_p를 더한 10채널)
- 용어는 처음 등장 시 한 줄 정의.
- 언어: **한국어** (기술 용어는 영어 병기).

## 7. 결과물 · 버전 관리

- 로컬 HTML + **claude.ai 비공개 링크**로 게시.
- GitHub **공개(public)** 저장소 `lidar-orin-slides` 에 CenterPoint와 함께 push. (GitHub Pages는 사용하지 않음)
- 폴더 구조 (모델별 폴더로 분리, CenterPoint와 같은 구성):
  ```
  lidar/
  ├── README.md              # 저장소 안내 (모델별 폴더 목록)
  ├── centerpoint/           # CenterPoint 슬라이드
  └── pointpillars/
      ├── README.md          # 프로젝트 소개, 보는 방법, 수정 방법

  ```
- 작업 단위(요구사항 확정, 슬라이드 완성 등)마다 커밋한다.

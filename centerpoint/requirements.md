# CenterPoint (LiDAR 3D 객체 검출) 구조·원리 설명 웹 슬라이드 — 요구사항 정의서

> 상태: **확정 v2** · 작성일: 2026-09-25 · 개정: 2026-09-25 (v2: 두 자료의 일관성 규칙 4.4, 3D 시각화 5.1, 한눈에 보기 3D 시퀀스 5.2 추가 → 23장)
> 확인 질문(8장)에 대한 사용자 답변과 추가 피드백(개념 우선)을 반영함.

---

## 1. 목적

NVIDIA Jetson **AGX Orin**에서 동작하는 **CenterPoint LiDAR 공식 모델**의 구조와 동작 원리를,
**입력(포인트 클라우드) → 출력(3D 바운딩 박스)** 까지 하나의 흐름으로 이해할 수 있는 **HTML 웹 슬라이드**로 만든다.
학습 원리와 Orin 배포(TensorRT) 실무까지 포함한다.

## 2. 대상 독자 · 용도

- **용도: 자습 후 발표.** 슬라이드 자체만 읽어도 이해되는 자습 자료이면서, 그대로 발표에 쓸 수 있어야 한다.
  - 화면(발표용)에는 그림·핵심 문장만, 상세 설명은 펼쳐보기/노트 패널(자습용)로 분리한다.
- 딥러닝/LiDAR 인식 **초보자**가 끝까지 따라올 수 있어야 한다.
- 동시에 실제 구현을 다루는 엔지니어가 봐도 **텐서 shape·연산 수준까지 정확**해야 한다.
- → "직관(왜?) 먼저, 수식·shape(어떻게?)는 그다음" 순서로 층을 나눠 설명한다.

## 3. 대상 모델 (확정)

- **NVIDIA 공식 `Lidar_AI_Solution / CUDA-CenterPoint`** (TensorRT 기반, AGX Orin 대상 배포 예제)
- 데이터셋: **nuScenes** (10클래스, 6개 task group)
- 원 모델: CenterPoint (Yin et al., CVPR 2021) VoxelNet 0.075 voxel 설정

아래 수치는 공식 저장소 소스·설정·ONNX 그래프로 검증함 (2026-09-25, master 기준).

| 단계 | 구성 | 검증된 사양 |
|---|---|---|
| 입력 | nuScenes LiDAR, 10 sweep 누적 | fp32 `[N, 5]` = x, y, z, intensity, time_lag (최대 300,000점) |
| 전처리 | CUDA 커널 3개: 해시 생성 → 복셀화 → 특징 추출 | 범위 [-54,54]×[-54,54]×[-5,3] m, 복셀 0.075×0.075×0.2 m, 격자 1440×1440×40 (spconv shape [41,1440,1440]), 복셀당 최대 10점, 최대 160,000 복셀, **점 평균**(학습 없음) → fp16 `[V,5]` + int32 `[V,4]`(b,z,y,x) |
| 3D 백본 | `SpMiddleResNetFHD`, libspconv (sm_87) | conv_input 5→16 → conv1 16 [41,1440,1440] → conv2 32 [21,720,720] → conv3 64 [11,360,360] → conv4 128 [5,180,180] → extra_conv 128 [2,180,180]; SparseConv 21개, 잔차 Add 8개 |
| 높이 압축 | ScatterDense + Reshape | `[1,128,2,180,180]` → `[1,256,180,180]` (TensorRT 엔진 입력) |
| Neck | RPN, layer_nums [5,5] | 블록0: 256→128, 180²(+1×1 conv→256) / 블록1: 128→256 s2, 90²(+deconv→256, 180²) → concat `[1,512,180,180]` |
| Head | CenterHead: shared conv 512→64, 6 task | car / truck·construction_vehicle / bus·trailer / barrier / motorcycle·bicycle / pedestrian·traffic_cone. 각 task: reg 2, height 1, dim 3(log), rot 2(sin,cos), vel 2, hm 1~2 → 출력 36개, 각 `[1,C,180,180]` fp16 |
| 후처리 | CUDA decode + 호스트 정렬 + CUDA rotated NMS | score>0.1, `x=(col+reg0)·8·0.075−54`, dim=exp, yaw=atan2(sin,cos), task당 최대 1000 후보 → NMS IoU 0.2 → task당 최대 83개 (max-pool peak 추출 없음) |
| 출력 | 박스 목록 | 11 float: x, y, z, w, l, h, vx, vy, yaw, label, score |
| 학습 | 원 CenterPoint | Focal loss(α=2, β=4) + L1 회귀(속도 가중치 0.2), loc 가중치 0.25, 가우시안 반지름(overlap 0.1, min 2) |
| 배포 | Orin, TensorRT 8.4, FP16 (INT8은 QAT 경로) | Orin 지연: 복셀화 1.36 / 백본 22.3 / RPN+Head 11.3(INT8 7.0) / 디코드+NMS 4.4 ms, 합계 ≈ 40 ms (23 FPS). 정확도 57.57 mAP / 65.64 NDS (PyTorch 59.55/66.75, 차이는 CUDA NMS 때문) |

## 4. 콘텐츠 요구사항

### 4.0 설명 원칙 — **개념이 먼저, 구현은 그다음** (최우선)
- 이 슬라이드의 주인공은 **CenterPoint라는 모델의 원리와 발상**이다. "Orin에서 어떻게 구현했나"는 그 원리를 실제로 돌리는 방법으로서 뒤따르는 부차적인 층이다.
- 각 슬라이드는 다음 순서를 지킨다.
  1. **핵심 질문** — 이 단계가 풀려는 문제를 한 문장 질문으로 던진다. (예: "점은 순서도 없고 듬성듬성한데, CNN을 어떻게 쓰지?")
  2. **직관·비유** — 수식 없이 그림과 일상적인 비유로 답의 방향을 보여준다.
  3. **원리** — 왜 그 방법이 문제를 푸는지, 다른 방법(대안)은 왜 덜 좋은지.
  4. **수식·shape** — 원리를 행렬 연산과 텐서 모양으로 정확히 확인한다.
  5. **구현 메모 (Orin)** — 같은 개념이 CUDA-CenterPoint에서 어떤 모듈로 돌아가는지. 작게, 또는 노트 패널로.
- 구현 세부(해시 테이블, 바인딩 개수, 호스트 정렬 등)는 개념 이해에 필요한 만큼만 화면에 두고 나머지는 노트 패널로 보낸다.
- "왜?"에 답하지 못하는 설명은 넣지 않는다. 숫자 하나도 "이 값이 왜 이 크기인지"를 함께 말한다.

### 4.1 전체 흐름 (필수)
- 초반에 **전체 파이프라인 지도**를 보여주고, 이후 모든 슬라이드 상단에 "현재 위치"를 표시한다.
- 각 단계마다 반드시:
  1. **무엇을 하는가** (동작)
  2. **무엇을 의미하는가** (입력 shape → 출력 shape)
  3. **왜 그렇게 설계했는가** (대안과 비교)

### 4.2 슬라이드 구성 (**23장**, 각 장 안에서 클릭으로 여러 단계 진행)

| # | 제목 | 핵심 질문 (개념) | 수식·구현 층 |
|---|---|---|---|
| 1 | 표지 | — | — |
| 2 | 문제 정의 | 점 구름에서 "물체"를 어떻게 찾아내나? 무엇이 어려운가(순서 없음·희소·거리별 밀도) | 입력 `[N,5]`, 출력 박스 9개 값 |
| 3 | 핵심 아이디어 | 물체를 "상자"가 아니라 **"중심점"** 으로 찾으면 무엇이 좋아지나? (anchor와 비교) | — |
| 4 | 전체 흐름 | 점 → 격자 → 3D 특징 → 위에서 본 지도 → 중심 찾기 → 박스, 각 단계가 맡은 역할 | 단계별 shape, 실행 모듈 |
| 5 | 한눈에 보기 (3D 시퀀스) | 점 구름 한 장이 박스 목록이 될 때까지, 같은 장면에서 무슨 일이 일어나나? (8단계) | 단계별 shape, 5.2 참조 |
| 6 | 입력 | 왜 여러 시점(sweep)을 겹치고, 시간 채널을 붙이나? | `[N,5]`, Δt |
| 7 | 복셀화 ① | 왜 점을 격자에 담나? (규칙적인 격자여야 합성곱이 가능) | 인덱스 계산 예제 |
| 8 | 복셀화 ② | 한 칸의 점들을 하나로 요약하는 법, 그리고 99.9%가 빈칸이라는 사실 | 평균, `[V,5]`, 희소성 0.13% |
| 9 | Sparse Conv ① | 빈칸을 계산하지 않는 합성곱은 어떻게 가능한가? SubM이 희소성을 지키는 이유 | dense vs sparse 연산량 |
| 10 | Sparse Conv ② | 희소 합성곱을 "행렬 곱" 문제로 바꾸는 방법 | gather → GEMM → scatter 토이 예제 |
| 11 | 3D 백본 | 왜 해상도는 줄이고 채널은 늘리나? (계층적 특징, 수용 영역) | 스테이지별 shape |
| 12 | BEV | 왜 위에서 내려다본 2D 지도로 바꾸나? | `[128,2,180,180] → [256,180,180]` |
| 13 | Neck | 작은 물체와 큰 물체를 한 번에 보려면? (두 스케일 결합) | conv를 행렬곱(im2col)으로 |
| 14 | Head 구조 | 지도의 한 칸이 대답하는 질문들: "여기가 중심인가? 어떤 크기·방향·속도인가?" | task group, 출력 채널 |
| 15 | Heatmap | "중심일 확률 지도"란 무엇인가, 왜 봉우리(가우시안) 모양인가 | 클래스별 채널, threshold |
| 16 | 회귀 | 위치·크기·방향·속도를 왜 이런 형태(offset, log, sin/cos)로 예측하나 | 디코딩 수식 예제 |
| 17 | 학습 ① | 정답 지도를 어떻게 만드나 (가우시안 반지름의 의미) | 반지름 계산 예제 |
| 18 | 학습 ② | 빈칸이 압도적으로 많은데 어떻게 배우나 (Focal loss의 발상) | loss 곡선, 가중치 |
| 19 | 후처리 | 봉우리에서 최종 박스까지, 중복 제거 | 디코딩, rotated NMS |
| 20 | 확장 개념 | 속도 예측이 **추적(tracking)** 을 공짜로 만드는 원리, 원 논문의 2단계 정제 (Orin 버전에는 없음) | — |
| 21 | Orin 배포 ① 개념 | 같은 모델을 왜/어떻게 더 빠르게 돌리나 (그래프 최적화, 층 합치기, 낮은 정밀도) | FP16/INT8, BN folding 수식 |
| 22 | Orin 배포 ② 실무 | 파이프라인이 CUDA 커널 / libspconv / TensorRT로 나뉘는 이유 | 단계별 latency, 메모리, 엔진 빌드 |
| 23 | 정리 (한 장 3D 지도) | 여덟 단계를 한 화면에: 같은 차·보행자가 단계마다 어떤 모양이 되나? 3D 장면 + 요약표, 용어집은 노트 | 단계별 shape (5.3) |

### 4.3 수학·shape 설명 (필수)
- 모든 주요 텐서의 **shape 표기** (예: `[N_points, 5]`, `[N_voxels, 5]`, `[1, 256, 180, 180]`).
- 핵심 연산은 **행렬 연산 형태로 풀어서** 보여주고, 작은 숫자 예시(toy example)에 실제 값을 대입해 한 번 더 보여준다.
  - 좌표 → 복셀 인덱스, sparse conv gather‑GEMM‑scatter, 박스 디코딩, 가우시안 타깃, focal loss.

### 4.4 두 자료의 일관성 (CenterPoint ↔ PointPillars) — 2026-09-25 추가
두 자료는 이어서 보는 한 세트다. 모델이 달라 내용은 달라도, **설명 방식·수준·깊이·포맷·시각화**는 아래 규칙으로 같게 맞춘다. 한쪽을 고치면 다른 쪽도 같은 규칙으로 점검한다. (상대 문서: `../pointpillars/requirements.md`)

| 항목 | 규칙 |
|---|---|
| 뼈대 (23장) | 표지 → 문제 → 핵심 아이디어 → 전체 흐름(2D 지도) → **한눈에 보기(3D 시퀀스)** → 단계별 설명 → 학습 ①② → 후처리 → 확장·비교 → Orin 배포 ①(개념) ②(실무) → 정리 |
| 슬라이드 블록 | 본문 슬라이드는 `Q`(핵심 질문) → `직관`(일상 비유) → 요점(`what` 동작 / `why` 이유 / `shape` 모양) → `ORIN 구현` 순서. 표지·지도(4장)·정리를 뺀 모든 장에 **Q와 직관 블록이 모두** 있어야 한다 |
| 수준·깊이 | 화면: 요점 한두 문장 + 수식 1~3줄 + 실제 값을 대입한 예제. 노트(N): 유도 과정, 설정값의 출처(파일·키 이름), 구현 파일·커널 이름, 그림 읽는 법과 과장·예시값 여부 |
| 수치 | 텐서 모양은 코드체 `[C, H, W]`. 모든 숫자에 "왜 이 크기인가". 공식 값이 아닌 것은 "예시값"·"설명용"으로 표시 |
| 색의 의미 | teal = 동작·입력, heat(주황) = 이유·핵심·양성, violet = 모양·특징, rose = 제거·경고. 3D 장면도 같은 의미로 칠한다 |
| 그림의 종류 | 공간이 있는 대상(점, 격자, 특징 지도, anchor·박스, heatmap)은 **회전 가능한 3D**, 순수 개념 도식·손실 곡선·표·행렬 토이는 **2D(SVG/HTML)** |
| 가상 장면 | 모델마다 가상 장면 하나를 만들어 모든 그림에서 재사용한다(같은 차, 같은 좌표가 장을 넘어 이어진다). 실제 데이터가 아님을 표지 노트에 밝힌다 |
| 장 번호 참조 | 본문·노트에서 다른 장을 "N장"으로 가리킨다. 슬라이드를 넣거나 빼면 참조를 모두 고친다 |
| 디자인·조작 | `src/head.html`은 제목만 다르고 같다. 슬라이드 엔진(단계 진행, 목차, 노트, 테마, 3D 엔진)도 같은 코드 |

## 5. 시각·인터랙션 요구사항

- **형식**: 단일 HTML 파일(브라우저에서 바로 열림, 설치 불필요).
- **단계별 진행**: 클릭 / →, Space 키마다 **한 단계씩** 요소 등장·애니메이션 진행. ← 키로 되돌아가기.
- **동적 시각화**
  - 포인트가 격자에 떨어져 복셀로 묶이는 애니메이션
  - 커널이 dense vs sparse 방식으로 움직이는 비교
  - 텐서 블록(직육면체)이 단계마다 크기·채널이 변하는 모습
  - 높이 방향을 채널로 "눕히는" 애니메이션
  - heatmap peak가 떠오르고 박스가 자라나는 애니메이션
  - 행렬 곱 셀 단위 하이라이트
- 진행 표시(현재 슬라이드/단계), 목차 바로가기, 자습용 상세 설명 패널(펼쳐보기).
- 다크/라이트 모드 가독성, 16:9 발표 화면 기준.

### 5.1 3D 시각화 — 2026-09-25 추가
- **엔진**: Three.js r128 (cdnjs). WebGL 렌더러 **하나**를 슬라이드 사이에서 옮겨 쓴다(브라우저의 WebGL 컨텍스트 수 제한과 메모리 때문). 장면은 처음 볼 때 만든다.
- **조작**: 드래그 회전, 휠 확대, `R` 시점 초기화. 가만히 두면 천천히 자동 회전하고, 드래그하면 멈춘다. 3D 영역에서 드래그한 것은 "다음 단계" 클릭으로 치지 않는다.
- **단계 연출**: 클릭마다 요소가 나타나고 사라지며(fade), 필요하면 크기 변화(납작해짐·솟아오름)·이동(제자리 찾아가기)으로 개념을 보여 주고, 카메라가 설명할 곳으로 부드럽게 옮겨 간다.
- **안정성**: three.js를 못 불러오면 3D 자리에 안내 문구를 띄우고 나머지 슬라이드는 그대로 동작한다. 다크/라이트 전환 시 3D 장면 색도 새로 만든다. `prefers-reduced-motion`이면 움직임을 생략한다.
- **과장 표시**: 칸 크기·높이 비율 등을 보기 좋게 바꾼 그림은 범례나 노트에 "과장"·"축소"를 적는다.
- **3D 슬라이드**: 23 정리(한 장 3D 지도), 2 문제, 5 한눈에 보기, 6 입력(여러 sweep), 7 복셀 격자, 8 복셀 한 칸(평균), 9 dense/sparse/SubM 합성곱, 11 해상도별 백본, 12 BEV 높이 압축, 13 Neck 특징 지도 판, 14 Head 출력 탑, 15 heatmap 지형, 16 박스 복원, 17 가우시안 정답 막대, 19 후처리·NMS (표지 포함 15장)

### 5.2 한눈에 보기 — 전체를 한 장의 3D 시퀀스로 (5장) — 2026-09-25 추가
- 목적: 단계별 설명에 들어가기 전에, **하나의 장면 위에서 입력 → 출력 전체가 변해 가는 모습**을 한 번에 본다. 발표 때는 이 장만으로 모델 전체를 설명할 수 있어야 한다.
- 형식: 슬라이드 1장, 클릭 **8단계**. 왼쪽은 3D 장면(위에 "현재 단계" 캡션), 오른쪽은 8단계 목록(현재 단계 강조, 이름 · 텐서 모양 · 한 줄 설명) + 직관 블록. 노트에는 단계마다 자세히 다루는 장 번호.
- 두 모델 모두 같은 레이아웃·같은 단계 수로 만든다.

| 단계 | CenterPoint 장면에서 일어나는 일 |
|---|---|
| 1 점 구름 `[N, 5]` | 10 sweep을 누적한 점 구름 |
| 2 복셀화 `[V, 5]` | 점이 든 칸만 상자로 (7.5 cm 대신 30 cm로 과장) |
| 3 3D Sparse 백본 `[128, 2, 180, 180]` | 0.6 m 칸, 높이 2층(센서 z −5~−1 / −1~3 m 경계 그대로) |
| 4 BEV `[256, 180, 180]` | 두 층이 내려앉아 판 한 장이 된다 |
| 5 Neck `[512, 180, 180]` | 더 두꺼운 판 |
| 6 Heatmap | 6개 task 지도의 최댓값을 지형으로, 물체 중심에 봉우리 |
| 7 회귀 → 후보 박스 | 점수 0.1 이상 칸마다 박스, 한 물체에 여러 개 |
| 8 NMS `[K, 11]` | 최종 박스 + 점수 + 속도 화살표 |

### 5.3 정리 — 한 장 3D 지도 (23장) — 2026-09-25 추가
- "한 장으로 보는 …" 정리 페이지는 **텍스트가 아니라 3D 시각화**로 만든다.
- 여덟 단계를 작은 장면(차 한 대 + 보행자 한 명) 하나로 각각 만들어 **4개씩 두 줄**로 늘어놓고 화살표로 잇는다. 한 화면에 전체가 보인다.
- 클릭 10단계: 전체 보기 → 단계 1~8에 카메라가 차례로 다가감(나머지는 흐리게) → 다시 전체 보기(학습·Orin 행 강조). 오른쪽 요약표(단계 · 핵심 발상 · 모양)의 같은 행이 함께 강조된다.
- 용어집은 노트 패널(N)로 옮긴다.
